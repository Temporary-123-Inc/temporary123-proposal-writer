# Ordered proposal workflow and resource checks

Use these steps for every new proposal. Read the applicable linked resources at each step and extract the facts needed for this opportunity; a link's presence is not proof that its content was reviewed. The other skill references supply detailed rules within this order. Respect the buyer's required document order even when it differs from the research order below.

Keep a working resource record outside the buyer-facing proposal: step, required answer, exact source link/path, page/table/row where applicable, fact or rate extracted, status and remaining question. Check the [bundled-source provenance](../assets/source-provenance.json) for snapshot dates, source links and asset hashes. Reuse an already inspected source within the task; re-open it only for a new detail, version change or unresolved issue. Use current user-approved project decisions over conflicting historical information.

## Source status and the user-facing table

Show a compact table in chat after the initial relevant-source pass and update it when answers materially change the status. At delivery, include the current table or a verified internal-note link within **Readiness** in the [four-part delivery report](delivery-report.md). Keep it outside the client-facing Word file. This table supplements the proposal; it does not replace the requested Word deliverable.

Use columns **Step | Source actually used (link) | Status | Missing information / next action**. Link the exact file, document, page or catalog row inspected, rather than only a broad folder when a specific source was used. Link the primary source alongside a local snapshot when appropriate. For sensitive forms, link only an authorized location and omit tax/bank details from the table.

- **Reviewed:** The applicable source content was read and supports the needed answer. Note the file/page/row and extracted fact in working notes.
- **Partial:** A source was reviewed but some needed field remains absent, inconsistent, too old or insufficiently specific. Identify that field.
- **Missing after checks:** The needed item was not found after checking the relevant indexed and directly browsed locations. State the search scope; do not claim the whole Drive lacks it.
- **Access blocked:** A known source could not be read. Ask for access or the relevant file/facts without treating a link as reviewed.
- **Not yet checked:** A resource is linked or listed but its applicable contents have not been read for this task. Do not call it missing or complete.
- **Not applicable:** This step/resource is unnecessary for the current scope; give the brief reason and do not request it.

For authoring and QA steps 10-11, report **Pending** until the artifact is written or the named checks are performed. Use **Completed** only for work actually performed, listing any narrow verification limitation; use **Partial** when work remains unfinished. Available tools or linked instructions alone do not prove completed authoring or verification. Source availability, content review, authoring and visual verification are different states.

Before labeling a required item missing, follow the links in the existing source guides, inspect relevant files and browse the designated folder and appropriate child folders if search is empty. Use the available supported facts first. Ask only for what this proposal still needs. Do not request a new price book, company profile or past-performance library when the existing one supplies the answer.

## Reusable library baseline

The package contains pricing rules/book, company/capability records, past-performance records, a cover-letter/style source, image links/fallbacks, Word helpers and the complete supplied inventory workbook with a technical JSON lookup. Use the inventory first for asset identity and supported specifications, retaining ItemID/sheet/cell provenance; it has 174 records, 173 named, with missing fields and known identity conflicts. These are existing resources to use, not items the user must recreate. The live source index also links a signed company W-9. The dated inventory does not establish current stock, unresolved specifications, approved regional service/personnel commitments, missing reference details or current qualification/insurance/financial proof. Check relevant records and ask only for additional evidence the new response needs. A new opportunity link and its project-specific facts are supplied per proposal rather than added as universal company defaults.
